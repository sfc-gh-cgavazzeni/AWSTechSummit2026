Motivation

The Problem We're Solving

What enterprises need

  • Analysts ask questions in natural language — "What's our return rate in the South?"
  • Data is split across structured + unstructured — SQL tables and freetext reviews live in different systems
  • Context must persist across turns — "Now focus on the bottom 3 regions" requires the agent to remember previous answers
  • Governance can't be bypassed — the AI must see only what the user's role allows
  • No new infrastructure to manage — no vector DB, no embedding pipeline, no model hosting

What we'll build today

Snowflake side: Cortex Analyst (SQL from natural language over a tuned Semantic View) + Cortex Search (hybrid semantic search over text data) + Cortex Agent + Managed MCP Server

AWS side: Bedrock AgentCore Runtime (managed execution environment) + Memory (multi-turn context) + Strands agent (Python) connecting to Snowflake via MCP

Key insight for SAs: "AgentCore solves the managed runtime and orchestration problem. Snowflake solves the governed data grounding problem. MCP is the open standard that eliminates any custom integration between them."

Module 2 · Cortex Analyst

From Natural Language to Correct SQL

How it works

1
User question

"What is our revenue by region year-to-date?"

2
Semantic View lookup

Analyst reads the SV to understand: revenue = SUM(total_amount) WHERE status='Completed', region = customers.region

3
SQL generation + execution

Generates precise JOIN + GROUP BY + filter, executes against Snowflake warehouse

4
Structured response

Returns table + optional chart recommendation + explanation of the SQL

Without vs with Semantic View

Without Semantic View
-- LLM guesses schema...
SELECT store_id, SUM(amount)
FROM orders GROUP BY 1

-- Wrong: uses store instead of customer
-- region; omits Completed filter
With Semantic View + Verified Queries
SELECT c.region,
SUM(o.total_amount) AS revenue
FROM orders o
JOIN customers c ON o.customer_id=c.customer_id
WHERE o.status = 'Completed'
AND YEAR(o.order_date) = YEAR(CURRENT_DATE())
GROUP BY 1 ORDER BY 2 DESC

Tuning tip: Verified Queries are the highest-ROI investment. 10 well-written VQs for your top KPIs will make Analyst answer those questions perfectly 100% of the time.

Semantic View: The Business Vocabulary Layer

What the RetailIQ SV defines

Key metrics defined

  • total_revenue: SUM(total_amount) WHERE status='Completed' — synonyms: revenue, fatturato, sales, gross sales
  • average_order_value: total_revenue / completed_order_count — synonyms: AOV, scontrino medio, basket size
  • return_rate: returned orders / total orders — synonyms: % returns, tasso resi
  • gross_margin_pct: (revenue - cost) / revenue

Tuning exercise: Verified Query

# In retailiq_semantic_view.yaml
verified_queries:
  - name: return_rate_by_category
    question: "What is the return rate
      by product category?"
    sql: |
      SELECT p.category,
        ROUND(100.0 * COUNT(CASE WHEN
          o.return_flag THEN 1 END)
          / NULLIF(COUNT(*),0), 2)
          AS return_rate_pct
      FROM orders o
      JOIN products p
        ON o.product_id = p.product_id
      GROUP BY 1
      ORDER BY 2 DESC

Workshop exercise: Ask Analyst this question before and after uploading the SV. Show the SQL diff. Then add your own VQ live using the UI editor.

Module 3 · Cortex Search

Hybrid Semantic Search — No Vector DB Required

What we're searching

RETAILIQ_REVIEWS_SEARCH
15,000 customer reviews with product feedback, store experience notes, delivery comments. Multi-lingual context (Italian store names, English text).

RETAILIQ_TICKETS_SEARCH
8,000 support tickets covering delivery issues, product quality, billing disputes, return requests.

How it differs from LIKE/ILIKE

  • Semantic: "package not received" finds "item still in transit", "shipment delayed"
  • Intent-aware: "unhappy customer" finds all negative sentiment even without the word "unhappy"
  • Hybrid: combines TF-IDF precision with embedding-based recall

Creation (one statement)

CREATE OR REPLACE CORTEX SEARCH SERVICE
  RETAILIQ_REVIEWS_SEARCH
ON review_text
ATTRIBUTES
  product_name, category, rating,
  sentiment_label, store_region
WAREHOUSE = RETAILIQ_WH
TARGET_LAG = '5 MIN'
AS (
  SELECT * FROM customer_reviews
);

Test queries for the workshop

  • "delivery problems southern Italy" → finds late packages in Sicilia/Campania
  • "customers unhappy electronics" → negative reviews without the word "unhappy"
  • "refund not processed" → billing tickets across categories

Module 5 · MCP Server

Snowflake Managed MCP Server

What "Managed" means

  • No infrastructure: No separate server to deploy or scale. Snowflake operates it as a platform service
  • Native auth: PAT tokens scoped to a specific role — not a generic API key
  • Automatic audit: Every tool call appears in Snowflake QUERY_HISTORY with full attribution
  • Any MCP client: Claude Desktop, VS Code, your own app, AgentCore — all work without any custom code

Create the server

CREATE OR REPLACE MCP SERVER
  RETAILIQ_MCP_SERVER
FROM SPECIFICATION $$
  tools:
  - name: "retailiq_analyst"
    type: "CORTEX_ANALYST_MESSAGE"
    identifier: "RETAILIQ_DB.ANALYTICS.RETAILIQ_SV"
  - name: "retailiq_reviews_search"
    type: "CORTEX_SEARCH_SERVICE_QUERY"
    identifier: "RETAILIQ_DB.ANALYTICS.RETAILIQ_REVIEWS_SEARCH"
$$;

PAT Token — scoped authentication

-- Run as ACCOUNTADMIN
ALTER USER retailiq_user
  ADD PROGRAMMATIC ACCESS TOKEN
    retailiq_mcp_token
  DAYS_TO_EXPIRY = 7
  ROLE_RESTRICTION = 'RETAILIQ_ROLE';

-- ⚠ Token shown ONCE — save it now!

Get your endpoint URL

DESCRIBE MCP SERVER RETAILIQ_MCP_SERVER;
-- endpoint: https://YOUR_LOCATOR
--   .snowflakecomputing.com/mcp/...

Save before next module: MCP endpoint URL + PAT token value + account locator. These go into the CloudFormation parameters.

Module 6 · AWS Bedrock AgentCore

AgentCore: Managed Agent Runtime

What AgentCore provides

Runtime: Managed Python execution environment — no EC2 instance management in production. Handles scaling, isolation, and execution state

Memory: Session memory that persists conversation history across turns. The agent "remembers" what was said earlier in the session

Gateway: Proxies outbound MCP calls to Snowflake. Handles retries, auth injection, and response validation

Observability: Built-in trace viewer showing tool selection decisions, latency per tool, and model reasoning

Workshop setup (CloudFormation)

1
Upload template

CloudFormation → Create Stack → Upload agentcore_cfn.yaml

2
Fill parameters

Snowflake MCP endpoint, PAT token, account locator — all from the previous module

3
Wait ~5 minutes

Stack deploys EC2 with Python 3.11 + Strands + credentials pre-loaded from Secrets Manager

4
Connect via EC2 Instance Connect

Outputs → EC2ConnectionURL → open in browser. No SSH key needed

Module 7 · Strands Agent

The Python Agent: Strands + MCP

from strands import Agent
from strands_tools import mcp_client

# Credentials auto-loaded from Secrets Manager on EC2
credentials = load_credentials_from_secrets_manager()

# Connect to Snowflake MCP Server
snowflake_mcp = mcp_client(
    url=credentials["snowflake_mcp_endpoint"],
    headers={"Authorization":
      f"Bearer {credentials['pat_token']}"}
)

agent = Agent(
    model="us.anthropic.claude-sonnet-4-5-v1:0",
    tools=[snowflake_mcp],
    system_prompt=RETAILIQ_SYSTEM_PROMPT
)

Multi-turn demo (shows Memory value)

Turn 1: "Analyze revenue by region for this year"
→ Agent returns regional revenue breakdown

Turn 2: "Focus on the bottom 3 — what are customers saying there?"
→ Agent remembers the regions, searches reviews for those regions specifically

Turn 3: "What actions would you recommend for those regions?"
→ Synthesizes quantitative + qualitative data into actionable recommendations

This is the "money demo": without AgentCore Memory, Turn 2 would not know what "the bottom 3" means. Memory is what transforms a stateless LLM call into a coherent business conversation.

Security: Dev vs Production

Workshop (today) Production
AuthPAT token, 7-day expiryPAT + short TTL rotation via Secrets Manager, ROLE_RESTRICTION to read-only role
NetworkOpen (0.0.0.0/0)Network Policy: whitelist AgentCore NAT Gateway IPs only
Role permissionsRETAILIQ_ROLE (all tables)Least-privilege read-only role; Row Access Policy for data segmentation
WarehouseXSmall, single clusterMulti-cluster with auto-scaling + query acceleration
MonitoringTerminal logsAgentCore traces + Snowflake QUERY_HISTORY + CloudWatch alarms

CREATE OR REPLACE NETWORK POLICY agentcore_only
  ALLOWED_IP_LIST = ('X.X.X.X/32', 'Y.Y.Y.Y/32') -- AgentCore NAT IPs from AWS console
  COMMENT = 'Restrict MCP access to AgentCore egress IPs';

Architecture Patterns

Choosing the Right Pattern

Scenario Cortex Native Agent AgentCore + Snowflake MCP
Primary use caseSnowflake-centric analytics teams, CoWork usersAWS-centric applications, multi-service orchestration
Agent frameworkSnowflake managed, no code requiredStrands, LangGraph, CrewAI, LlamaIndex, OpenAI SDK — any framework
Memory / contextSession-level in CoWorkAgentCore Memory (configurable retention, cross-session)
External toolsCortex tools onlyAny AWS service + Snowflake + other MCP servers combined
Runtime managementFully managed by SnowflakeFully managed by AWS AgentCore Runtime
Governance scopeSnowflake RBAC end-to-endSnowflake RBAC for data + AWS IAM for infrastructure
Best forSingle-stack Snowflake deployments, internal analyticsMulti-cloud agentic apps, integrating Amazon Location / Bedrock KB / S3

These are complementary, not competing. Many customers run the native Cortex Agent for internal analyst teams while AgentCore powers customer-facing applications — both pointing at the same Snowflake data via MCP.
